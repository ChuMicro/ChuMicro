  **Design refinements (from 2026-04-26 conversation, captured before they're lost):**

    - **Deploy owns a scoped subset of device storage**, not the whole filesystem.  Specifically: `/lib/*`, the canonical entrypoint (`/code.py` on CP, `/main.py` on MP), `/active.py`, and `/runtime_config.msgpack`.  Anything outside that scope — user-uploaded images, manually-edited `boot.py` overrides, hand-tuned `settings.toml` knobs — is the user's territory and never gets touched by an ordinary deploy.
    - **Diff = scan + remove + write**, not manifest math.  The deploy reads what's currently in scope on the device (`os.listdir("/lib/")` etc.), computes "what's there but not in the new payload" = stale, deletes those, writes the new files.  No persistent on-device manifest, no risk of manifest drift, no extra file format.  The transport already has the bookkeeping.
    - **MP needs a `/lib/` convention** to match CP's.  MP supports it (`sys.path` includes `/lib` on most ports) but doesn't enforce it; chumicro-workspace deploys should put every library there so the scope rule above applies uniformly across runtimes.  Workspace's existing CP convention carries over verbatim.
    - **`--wipe` flag for the destructive case** — when the user deliberately wants a clean slate (e.g., recovering from corruption, freeing space, full reflash prep): full filesystem erase before deploy.  CP: `storage.erase_filesystem()` (already used by the flash-audit cleanup helper).  MP: walk root + delete everything.  Out-of-scope for ordinary `deploy` / `switch` calls.
    - **`switch` becomes an alias for `deploy`** (or goes away).  `multi_thing_boot_source`, `--boot-shim`, `--active`, the side-by-side `/lib/things/<each>/` layout — all retire.

  **Sequencing:** wait until Phase 7 ships a real first-sensor thing.  Build a second simple thing (heartbeat blinker, button counter — anything cheap) as a fixture.  Measure the flash budget + deploy-time tradeoffs on real hardware: CP flash, CP RAM, MP flash, MP RAM.  Then commit to the redesign and rip multi-thing out in one focused workstream — chumicro-deploy's transport layer gains the scan-and-delete primitive, chumicro-workspace's CLI surface drops the multi-thing commands, the workstream doc closes Phase 4a's polish addendum with a "superseded by …" note.
