## Investigations

- [ ] **`__slots__` audit across libraries — drop where it provides no value** (filed 2026-05-11) — `__slots__` is currently used in 9 library files across 17 declarations (`chumicro_mqtt._wire`, `chumicro_mqtt.client`, `chumicro_requests.client`, `chumicro_requests.testing`, `chumicro_runner.core`, `chumicro_timing.heartbeat`, `chumicro_timing.testing`, `chumicro_http_server.server`, `chumicro_compat.functools`).  Verified during this session: MicroPython has no `__slots__` implementation ([discussion #13745](https://github.com/orgs/micropython/discussions/13745)), CircuitPython inherits the no-op behaviour, and CPython is the only runtime where it saves RAM (drops the per-instance dict) + locks the attribute set.  So the on-device value is zero and the only on-CPython value is catching typo'd attribute assignments in tests.  Audit candidate is to walk each declaration: does *any* of this class's CPython-test surface benefit from attribute-locking (many similarly-named fields where a `self.feild = ...` typo would silently shadow a real attribute)?  If no → drop the line, save the source bytes.  If yes → leave with a brief comment naming the typo risk.  The new `/audit-embedded` skill's §7 "Code shape" covers this dimension and the [`plans/patterns.md` "`__slots__` on MicroPython and CircuitPython"](patterns.md) section is the durable record; this entry just queues the per-library execution.

- [ ] **MicroPython default `ssl.wrap_socket` skips certificate validation — surface in chumicro_sockets** (filed 2026-05-11) — bench-verified during a README TLS-claim audit: on Pi Pico W MP and Lolin S2 MP, `ssl.wrap_socket(sock, server_hostname=host)` with no explicit context accepts ANY cert, including the expired one at `expired.badssl.com`.  Same bench: CircuitPython on the same two boards correctly rejects `expired.badssl.com` with `MBEDTLS_ERR_X509_FATAL_ERROR` via the firmware-bundled mbedTLS CA store (CP ships `x509-crt-bundle`; MP doesn't).  Affects: (a) `libraries/sockets/src/chumicro_sockets/_adapters/mp.py` `connect_tls` (~line 161) defaults to no-verify silently; (b) `libraries/sockets/src/chumicro_sockets/__init__.py` `connect_tls` docstring claims `ssl.create_default_context()` "picks up the system trust store" on every runtime — true on CP, false on MP; (c) every consumer that uses `HttpClient.from_config({}, radio=...)` / `MQTTClient.from_config({}, radio=...)` on MP gets insecure TLS by default with no warning, and (d) the README claim about default trust stores was rolled back 2026-05-11 to avoid misleading users until this is resolved.  Fix shape TBD — candidates: bundle a curated PEM (Let's Encrypt / DigiCert / Cloudflare roots) and load it in the MP adapter; or raise on MP when `connect_tls(context=None)` to force opt-in via `ssl_context_with_ca(...)`; or set `cert_reqs=ssl.CERT_REQUIRED` and surface the missing-CA failure loudly.  Reproducer scripts (CP + MP variants of an `expired.badssl.com` probe) were live-tested under `.scratch/tls_validation/` during the audit — paths gone but the shape is straightforward to recreate.
