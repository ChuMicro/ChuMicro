- [ ] **`discover` should appendably register plugged-in boards** — today `discover` just lists the serial ports the host sees (read-only); to populate `devices.yml` users have to run `add-device <id> --address <port> --runtime <cp|mp>` per board, including spelling out the runtime even though `probe_device` could infer it.  After the Decision 0038 pivot `devices.yml` is gitignored + materialized at setup, so it starts empty on every fresh clone — making this friction more visible.  Possible shapes: (a) `add-device --auto` with no args probes every port, infers runtime from the response, prompts the user for an id per new board, appends to `devices.yml` (interactive, opt-in); (b) `discover --register` does the same as a side-effect; (c) `add-device --from-port <port>` skips `--runtime` and infers it from probe — minimal change, scriptable; (d) leave as-is (the current `discover` + per-board `add-device` works, just chatty).  The chumicro mono-repo today goes (d) and it's tolerable for 4 known boards; a project-workspace user with N boards is a worse fit.  Lean: ship (c) as the small low-risk win, hold (a)/(b) until a user with five-plus boards complains.  Out-of-scope until Phase 7 surfaces a real multi-board need.
- [ ] **Re-evaluate multi-thing-on-one-device flash cost** — Phase 4a polish landed `multi_thing_boot_source` + `switch <name>` (ships every thing's payload to the device side-by-side under `/lib/things/<each>/`).  After the 2026-04-26 Pi Pico W flash audit (Decision 0037 + macOS-FAT hygiene; ~80 KB recovered to fit all 9 libs into ~870 KB CIRCUITPY space), the multi-thing semantics may be the next flash-bloat exposure: a two-thing deploy on Pi Pico W could blow the budget if either thing pulls in non-trivial libraries.  Decide between (a) keep multi-thing as-is and document the flash budget, (b) gate it behind a `multi_thing: true` workspace.yml flag with a pre-flight size check, (c) require explicit `--allow-multi-thing` per deploy, or (d) drop multi-thing entirely (`switch` becomes a re-deploy, not a re-pointer).  Don't redesign until a real two-thing workspace surfaces — but flag this before users hit the wall.
