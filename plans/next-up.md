- [x] **`chumicro-deploy` recovery-layer hardening + macOS FSKit wedge detection** — follow-on pass after live hardware testing surfaced gaps.  New `chumicro_deploy.macos_fskit` module + `DeployFailureKind.MACOS_FSKIT_WEDGED` (tenth kind): on darwin, when a `CIRCUITPY_DRIVE_MISSING` error fires, `InteractiveDeployer` probes `ps -o state= -p $(pgrep diskarbitrationd)` and, if the daemon is in uninterruptible wait (the signature of the user-space msdos FSKit extension wedging `diskarbitrationd`), promotes the kind and surfaces the exact recovery command — `sudo killall -9 com.apple.fskit.msdos fskit_helper fskitd fskit_agent diskarbitrationd && launchctl kickstart -k gui/$(id -u)/com.apple.DiskArbitrationAgent`.  The per-user `DiskArbitrationAgent` has to go through `launchctl kickstart -k` rather than `killall` because its plist has `KeepAlive=false`; without the agent restart the drives mount but Finder's Locations sidebar never registers them.  Classifier fixes from the same session: CIRCUITPY drive patterns now checked before port-unavailable (stale-mount `EACCES` was misrouting to `PORT_UNAVAILABLE`); `"failed to access"` + `"it may be in use by another program"` added to port-unavailable patterns so mpremote's missing-device message stops landing in `BOOTSTRAP_EXEC_FAILED`; `CIRCUITPY_DRIVE_MISSING` plan text rewritten so RESET is the primary fix (works for both flash-mode and Finder-eject) with unplug/replug as fallback for boards without a RESET button; `MACOS_FSKIT_WEDGED` plan includes a heads-up about the known Apple FSKit-Finder sidebar regression.  Transport-level: `CircuitpythonTransport._resolve_circuitpy_drive` writes a `.chu-probe` marker to catch EACCES up-front instead of halfway through rsync.  Demo additions: new `scenario_flash_copy_failed` (forces a 2 MiB payload against ~1 MiB CIRCUITPY, verifies `FLASH_COPY_FAILED` coaching); `scenario_circuitpy_drive_missing` now re-resolves `_build_flash_device` on demand so drives that came back mid-session don't require restarting the script.  435 host-side tests (+2 regression, +12 new FSKit-module cases); `macos_fskit.py` at 100 % coverage; workspace stays at 94.17 %.
