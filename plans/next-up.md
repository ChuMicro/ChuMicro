- [ ] **Empty parent dirs survive `delete_files` and shadow `/lib/<name>/` via namespace-package import** (surfaced + root-caused 2026-05-19, curated-mode 4-board bench) — Two-part defect, root cause settled.  Clarification on Decision 0077: the bench output `deploy: removed stale /<path>` IS clean-slate behavior — `clean=True` enumerates the whole device (minus keep set) and reconciles, the user-visible diff is per-file deletions, not a single `wiping filesystem` line; the 0077 default-flip is in force.  The bug is downstream of that: `chumicro_deploy.deployer.deploy_diff`'s pre-stage hook calls `transport.list_files_in_scope(clean_slate=True)` (file-only walk; the MP `_LIST_ALL_SCRIPT` and CP `_list_scope_on_drive` both emit only files, never directories) → `stale = on_device - files` → `transport.delete_files(stale)` — which reaps files but leaves their parent directories behind empty.  In the S2 MP failure the device carried `/chumicro_timing/<file>.py` at root from a prior deploy convention; the new payload's `/lib/chumicro_timing/<file>.py` is at a different prefix, so the root-level files all entered `stale`, got deleted, and `/chumicro_timing/` orphaned as an empty directory.  Second half, bench-confirmed: MicroPython's `sys.path` default is `['', '.frozen', '/lib']` with `''` (root) FIRST — an empty `/chumicro_timing/` at root resolves `import chumicro_timing` to an implicit namespace package (PEP 420 shape; `__file__` is `None`, `dir()` empty) and shadows the populated `/lib/chumicro_timing/` deeper in the path.  Repro on a cleaned board: `os.mkdir('/foo'); ts.fs_writefile('/foo/_x.py', ...)` then `chumicro-workspace deploy <any project> --device <mp-board>` → "removed stale /foo/_x.py" but `/foo/` survives → `import foo` succeeds as an empty namespace module.  Fix surface is small: after `transport.delete_files(stale)`, reap directories that are now empty (walk unique parents of `stale`, `os.rmdir` bottom-up).  CP host-side drive walk has the analog gap (parent dirs left empty after `Path.unlink`); same fix shape applies there.  Pi Pico W boards didn't trip it because their pre-existing layout matched the new payload's prefix; the failure is deterministic against any board whose history straddles a layout change.
