- [x] **Runner stale-fd busy-spin — REAL, fixed 2026-08-07 (runner 0.19.2).**  `_sync_poll_set` unregistered by object; CPython keys its poll set by descriptor read off the object at unregister time, and a closed socket answers -1, so the unregister raised, the sweep swallowed it and popped the slot anyway, and the descriptor stayed in the kernel set forever.  `poll()` then returns POLLNVAL instantly and `_POLL_ERROR_MASK` (POLLERR|POLLHUP) ignores it, so `wait()` never blocks again — a board that stops sleeping after its first completed fetch.  Slots now carry the descriptor recorded while the socket was open and the sweep retries with it, skipping the retry when a live slot already claims that descriptor (a freed fd goes straight to the next socket opened).  The pre-existing test used a poller keyed by `id(obj)`, which cannot strand anything, so it could never have caught this.  Costs 812 stripped B and leaves runner at **98.6 % of its ceiling (285 B headroom)** — the next `core.py` change needs a budget conversation.  The reported `send_budget_per_tick`/POLLHUP race does NOT reproduce: POLLHUP only reaches a service's `io_error` hook, which neither http_server nor websockets defines, and the sockets those two throttle never enter the poll set.  Parked: `_POLL_ERROR_MASK` still excludes POLLNVAL, so a socket closed out-of-band while its service still reports interest would busy-spin the same shape from a different cause; no caller demonstrated, mask left alone.
