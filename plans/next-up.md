- [ ] **`chumicro_http_server` body buffer — mirror `chumicro_requests` three-tier shape** (filed 2026-05-14, supersedes the dropped recv-scratch bullet from `/audit-workspace` 2026-05-11) — `chumicro_requests._wire.HttpResponseParser` (`libraries/requests/src/chumicro_requests/_wire.py:520-583`) already runs three tiers on the **body accumulator**: (1) caller-owned `body_buffer` kwarg for steady reuse — `HttpClient` passes a long-lived buffer for cross-request reuse; (2) oversized responses rebind `_body` to a one-shot `bytearray(content_length)` sized-to-fit, freed when the parser is dereferenced; (3) `max_body_bytes` enforcement is the error tier.  `chumicro_http_server._wire.RequestParser` (`libraries/http_server/src/chumicro_http_server/_wire.py:283`) does not — single `bytearray()` that grows via `extend`, allocated per request per connection.  Work shape: add a `body_buffer` kwarg to `RequestParser.__init__` matching the requests signature; `Connection` in `server.py` owns a long-lived body buffer per connection and passes it in; on `_enter_body_state` if `Content-Length > body_buffer capacity` rebind `_body` to `bytearray(content_length)` sized-to-fit; if `Content-Length > max_body_bytes` reject with 413 before any allocation (HTTP semantics — error, not rolling-discard like MQTT).  **Layer distinction — the previous bullet conflated two buffers; do not repeat that mistake.**  This work is the *body accumulator* layer (the parsed-body buffer the parser writes into).  It is NOT the *recv-scratch* layer (`server.py:220` `bytearray(min(recv_budget, 512))`, mirrored in `requests/client.py:474` and `websockets/_session.py:172`).  Recv-scratch is per-tick I/O staging — bytes drain through it into the parser.  The 512 cap is a per-library throughput knob; requests / http_server / websockets happen to share `512` by coincidence on a 124 KB heap, but each library's recv-scratch sizing is a function of its own protocol shape and stays per-library.  Don't try to export `MAX_RECV_SCRATCH_BYTES` from `chumicro_sockets` and don't dedup the recv-scratch sites as part of this work.  **Bench-validated constraint to preserve** — `chumicro_requests` deliberately does NOT pre-allocate a default-sized body buffer in standalone use; `test_small_body` + `test_large_body` in `functional_tests/test_memory_fragmentation_on_device.py` regressed with a 1024-byte default, because geometric growth via `extend` primes the small-allocator tiers in a way the on-device allocator can recycle cleanly between iterations.  Long-lived consumers (`HttpClient` today, `Connection` after this work) pass `body_buffer` for steady-state reuse without the regression.  Mirror this in http_server — `RequestParser` starts empty in standalone use; `Connection` supplies the long-lived buffer.  **Keep-alive interaction** — the cross-request reuse angle has marginal payoff today because every response emits `Connection: close` and the socket closes after drain (parked in `workstreams/http-server-deferred-features.md` item 4).  Body-buffer work still earns its keep on the sized-rebind + 413-before-alloc tiers; the cross-request reuse value compounds when keep-alive lands.  **Related work** — the websockets three-tier inbound bullet (also queued in `## Next`) is the frame-level equivalent for that library and applies MQTT's pattern with rolling-discard at tier 3; this one is the message-level equivalent for http_server with HTTP-shaped 413-reject at tier 3.
