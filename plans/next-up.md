- [ ] **`library` manager doesn't honor "I own this now, leave it alone"** (surfaced 2026-05-19, user-edited sockets after `library forget`) — `fetch_closure` walks every chumicro dep in the new add's pyproject closure and calls `_place_library` for each, which unconditionally `_backup_existing` → replaces the live tree.  `library forget` drops the row but doesn't prevent a *later* `library add chumicro_http_server` (or anything with `chumicro-sockets` in its closure) from re-pulling sockets and shoving the user's edited copy into `_library-backups/`.  The edit-preservation contract is "snapshot-aside, never silent clobber" — safe, but not what a user editing a library locally actually wants (their edits stop being *live*).  Two candidate designs to pick between: (a) a `local_edits: true` flag in the curated `libraries:` row that the closure walker respects (skip `_place_library` for flagged rows + emit a notice "kept your edited tree at libraries/<name>; channel has v0.X.Y if you want it"); (b) hash-detection — compare on-disk tree against the channel's snapshot, and if it diverges, prompt / refuse silently.  (a) is more discoverable + scriptable; (b) is zero-config but heavier and surprises users mid-resolve.  No code change yet; design decision first.
