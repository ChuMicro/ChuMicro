- [ ] **workbench/deploy CircuitpythonTransport tests — eliminate real `subprocess.run(["sync"])` calls** (filed 2026-05-12 during preflight-timing investigation) — six tests in `test_circuitpython_transport.py` (`test_waits_for_board_to_see_new_entrypoint`, `test_post_rsync_verification_failure_raises`, four `TestWipeFilesystem::test_flash_mode_*` cases) collectively cost **~80 s of wall-clock time** out of preflight's 73-s `test` phase.  Each runs `flash_drive.flush_volume`, which on macOS calls `subprocess.run(["sync"], check=True)` — a real OS-level filesystem flush that blocks until ALL pending host writes commit.  With concurrent test runs / IDE indexing / `git` operations in the background, each `sync` blocks for many seconds.  In isolation each test takes 0.10 s; in the file together they take 10–24 s each.  Fix shape: thread a `subprocess_run` injectable through `flash_drive.flush_volume` defaulting to `subprocess.run`, with tests passing a fake that returns immediately.  ~30 LOC + test updates.  Preflight wall time should drop from ~75 s to ~15 s post-fix (workbench/deploy goes from 107 s → ~25 s, and the slowest *remaining* phase becomes either docs at 4 s or the test fan-out for one of the larger libraries).  This is the single biggest preflight-speed lever in the workspace today.
