# Decision 0026: Editable installs as standard workspace setup

Status: `accepted`
Date: `2026-04-09`
Related: none

## Context

The workspace originally used IDE source-root configs (PyCharm content
roots, VS Code `extraPaths`) as the sole mechanism for import resolution.
Editable pip installs were explicitly rejected early on — the maintainer
described them as "opening windows for uncertainty" (see Rejected approach
#1 in `plans/history.md`).

This caused recurring problems:

1. **Editors without dedicated config generators** (Neovim, Helix, Emacs,
   Sublime) could not resolve cross-library imports at all.
2. **CLI tools** (`python -c`, debuggers, REPLs) required manual
   `PYTHONPATH` setup or running through `run.py`.
3. **Root `conftest.py`** had to add every `src/` directory to `sys.path`
   at import time — a fragile shim duplicating what pip already does.
4. Every new resolution mechanism (IDE config, conftest, PYTHONPATH in
   run.py) had to be kept in sync with the library list.

The original "uncertainty" concern was unfounded: in a development workspace,
editable installs point at the exact same source files as source-root configs.
No copies, no build artifacts, no version ambiguity.

## Decision

`pip install -e` is the standard workspace setup for all libraries.

1. **`python scripts/run.py setup`** installs all libraries under
   `libraries/` as editable packages.  Third-party dev dependencies are
   installed from `requirements-dev.txt`.
2. **`python scripts/run.py new-library <name>`** installs the new library
   as editable immediately after scaffolding.
3. **IDE source-root configs** (generated by `sync-ide`) remain as an
   additional layer for IDE-specific features (test discovery, type
   checking).  They are not the primary import resolution mechanism.
4. **Root `conftest.py`** still adds `sys.path` entries as a fallback for
   CI environments or fresh clones before `setup` has run.
5. **`run.py test`** sets `PYTHONPATH` independently, so tests do not
   depend on editable installs being present.

### Alternatives considered

- **Source roots only (previous approach):** Required per-IDE config
  generators and left CLI/REPL/unsupported-editor users without import
  resolution.  Rejected — editable installs solve the problem universally.
- **`PYTHONPATH` export in shell profile:** Fragile, stale across library
  additions, invisible to editors.  Rejected.
- **Regular pip install (non-editable):** Copies source into
  `site-packages`, so edits require re-installation.  Rejected — defeats
  the purpose of a development workspace.

## Consequences

- Imports work in any Python tool after `setup` — no per-editor
  configuration required.
- `sync-ide` is still needed for IDE test discovery and type-checking
  configs, but import resolution is no longer its responsibility.
- The `AGENTS.md` common pitfall "do not use `pip install -e` manually"
  remains: agents should use `run.py setup` which handles editable
  installs along with everything else.
- Adding a new library (via `new-library`) automatically makes it
  importable workspace-wide.
