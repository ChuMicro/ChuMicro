## Why

Decision 0115 collapsed the factory *bodies* into one shared module but left the five `from_config` call sites free to diverge, and they have — the M77 drift class recurring one layer up, in signatures and error strings instead of bodies.  Separately, the workspace tooling has three write-paths that surprise: `update` can silently discard in-flight edits, `library add` dirties a tracked file by design, and the ownership taxonomy is restated by hand in three documents (one already drifted and was fixed in the template repo 2026-08-09).  None of this is broken today; all of it is the kind of incoherence that compounds as consumers arrive.

## Library seam items

1. **`ticks=` seam forwarded only by mqtt — LANDED 2026-08-09.**  `patterns.md` §"from_config must forward the ticks seam" records this as a bench-bitten rule for *all* factories.  ntp and websockets gained explicit `ticks=` forwarding; requests got it through the Decision 0118 `**kwargs` passthrough.
2. **websockets server binds eagerly at construction — LANDED 2026-08-09.**  `WebSocketServer` now takes exactly one of `listener=` (pre-built escape hatch, kept) or `listener_factory=` (deferred; the first `handle()` tick binds and forces non-blocking, mirroring http_server's `transport_factory`).  `from_config` passes the factory without calling it, so construction is side-effect-free; `io_socket` stays `None` pre-bind and `io_interest` reports 0, per the Decision 0080 reactor contract.
3. **Non-blocking is not part of the shared factory contract — LANDED 2026-08-09.**  Call: builders guarantee non-blocking.  `connector` and `listener` already documented the guarantee; `udp_socket_factory` now applies `setblocking(False)` itself and says so, and ntp's private re-wrap (`non_blocking_udp_factory`) is deleted.  mqtt's `_force_non_blocking` stays: it guards caller-supplied `socket=` objects and MicroPython TLS adapters that lack `setblocking`, which no factory contract can cover.  The raw `chumicro_sockets.udp_socket` builder keeps its blocking default; only the factory layer promises non-blocking.
4. **Five wordings of the skip-factories `RuntimeError` — LANDED 2026-08-09.**  One canonical string at all six sites (mqtt/requests/http_server client-side, websockets server + client, ntp): ``chumicro_sockets.sockets_factory not available (excluded via __chumicro_skip_factories__ or not on the board); pass <hatches> explicitly.``  Each site's ``<hatches>`` names its real escape kwargs (`transport_factory= or socket=`, `transport_factory=`, `listener= or listener_factory=`).  A shared formatter in chumicro_sockets was rejected: the message exists precisely for when that module is absent.
5. **wifi is the odd library out — LANDED (in two waves, both 2026-08-09).**  First wave: constructor side effect removed (`configure()` deferred to the first attempt), CPython fallback moved out of `testing.py` into `_adapters/cpython.py` (`CpythonWifiAdapter` host stand-in), module-top `ticks` import replaced by the lazy DI fallback.  This wave: `WifiService.from_config(config, *, radio=None, ticks=None, **constructor_kwargs)` in the Decision 0118 shape — `wifi.*` keys load through the unchanged `WifiConfig.from_config`, extra kwargs pass through, explicit `adapter=` beats `radio=`, and `radio=` reaches only the CircuitPython adapter.  README / index / guide / `connect_to_ap.py` now show the one-call form.
6. **Three documented spellings for the radio handle — docs CONVERGED 2026-08-09.**  Call: no forwarding property (patterns.md ban stands); every library README/guide/index snippet now spells the handle `wifi.adapter.radio` off a bound `WifiService`, including the mqtt/sockets/ntp sites that taught bare `radio=wifi.radio`.  Two deliberate keeps: substrate-level docstrings in `chumicro_sockets` (and its CP adapter error) still name the raw `wifi.radio` object, because that layer neither knows nor requires chumicro-wifi; and the six `examples/helpers.py` `wifi_up()` bootstraps still drive the runtime's built-in wifi, because rewriting them onto chumicro_wifi grows every example's on-device dependency closure and needs board time — surface again if examples should showcase `WifiService` instead.
7. **`Runner.handler_errors` is a write-only metric — LANDED 2026-08-09.**  Counter + last-error pair adopted: `Runner.last_handler_error` holds the most recent isolated exception (a raising `on_handler_error` callback replaces it, matching the double-count).  (Correction to the recorded claim: http_server carries only the bare `accept_errors` counter; the pair precedent was websockets' `last_error`.)

## Workspace-tooling items

8. **`update` has no dirty-worktree guard and no backup — LANDED 2026-08-09.**  `update` now records a per-file fingerprint of what it applied in `.chumicro-template-state.json` (workspace-root machine state; the template repo still needs the gitignore entry) and refuses to overwrite a tool-owned file whose on-disk fingerprint differs from the last-applied one unless `--force` (CLI exit 3 with a `--force` hint; clean siblings still apply).  A file with no recorded baseline is overwritten as before and the run records baselines, so the guard arms from the first state-recording update; no merge model.
9. **`update` never deletes — LANDED 2026-08-09.**  `update` reconciles deletions from the same fingerprint record: a file it applied earlier that upstream no longer ships is deleted (REMOVED, empty parent dirs pruned), with the item-8 guard (locally-modified deletion candidates refuse without `--force`).  Manifest-driven, so user-created files inside tool-owned directories (custom sibling workflows) are never touched.  `_walk_tracked_files` renamed `_walk_regular_files`.
10. **`library add` writes machine state into a tracked file — LANDED 2026-08-09 (call: commit-it).**  The entries are not machine state: acquired `libraries/<name>/` trees are committable workspace content and `extraPaths` mirrors that set machine-independently, so the stance is documented (module docstring + the `library add` CLI note now says commit it alongside the acquired trees).  Template-checkout dirt only occurs when the checkout has acquired libraries, which is already dirt.  Template repo still needs a `pyrightconfig.json` row in its AGENTS.md ownership table.
11. **Ownership zones are stated in four places — LANDED 2026-08-09.**  Decision-0079-style checker `template_zone_docs.py` (`python -m chumicro_workspace.template_zone_docs <root>`, exit 1 on drift) verifies the AGENTS.md ownership table, the CONTRIBUTING.md "only touches" list, and README "folder is tool-owned" claims against `template_zones.py`.  Run against the live template checkout it flags the real drift (CONTRIBUTING missing `requirements.txt`, plus the item-12 `constraints.txt` rows); template repo needs those doc edits and a CI step invoking the module.
12. **Template CI installs from `>=` floors with no lockfile — LANDED 2026-08-09 (chumicro-workspace half).**  `constraints.txt` is now a tool-owned zone entry so `update` re-flows pins once the template ships them.  Template-repo half: commit a `constraints.txt` with `==` pins for the requirements.txt floors, and pass `-c constraints.txt` in `run.py setup`'s regular-mode install and CI; rollback becomes `update --ref <last-good>`.
13. **`pyproject.toml` is tool-owned but holds user knobs beyond `[project].dependencies` — LANDED 2026-08-09 (call: loud, not merged).**  The item-8 guard covers `pyproject.toml` with a dependencies-blind fingerprint (parsed document minus `[project].dependencies`), so a dependency-only edit still flows silently through the tomlkit carve-out while any other knob edit refuses without `--force`; an unparseable on-disk file also refuses instead of silently overwriting.  Extending the carve-out per-knob was rejected as a growing merge model, which item 8 rules out.
